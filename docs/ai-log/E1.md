# E1 — Steps, cursors, and the run state machine

## Prompt

Task E1 of `IMPLEMENTATION.md` §14: sequential execution, event cursors, per-step and global deadlines, and
fail-fast. Done when unit tests with a fake runtime cover ordering, deadlines, and stale observations before
the cursor.

## Summary

- `scenarios/engine.py`: `execute(scenario, handlers, source)` runs the steps in order. Each step runs the
  handler of its action, which can read the events through a `Source` and wait for a matching event after its
  cursor (`Context.cursor`, `Context.wait_for`). A step has its deadline (asyncio's clock) and the scenario
  has its global deadline. A step that does not pass stops the run when fail-fast is on.
- Verdicts: PASSED, FAILED (a check did not hold), TIMED_OUT (a step's deadline, or the global deadline
  during the step), UNSUPPORTED (no handler for the action), ERROR (an unexpected exception). A run is ERROR
  when a verdict is ERROR or UNSUPPORTED, FAILED when a verdict is not PASSED or the global deadline passed,
  and PASSED otherwise.
- `RunMachine`: a run is pending, then running, then one of the ended statuses; any other move raises
  `InvalidTransition`.
- D-017 records the design.

Dependencies: none new. The models of C4 (the scenario, the steps, the verdicts, and the run states).

## Verification

- `tests/unit/test_scenario_engine.py` (10 tests, against a fake runtime):
  - the steps run in order and all pass; the progress is complete;
  - a stale event before the cursor is not matched, even when the source returns it, and the step matches the
    event after the cursor (seq 3, not the stale seq 1);
  - a step without its event times out at its own deadline, as TIMED_OUT, and the run is FAILED;
  - the global deadline ends the run during the step in progress, which gets TIMED_OUT, and the later steps
    do not run;
  - fail-fast stops after the first step that does not pass; without it, the later steps still run;
  - an action with no handler is UNSUPPORTED, and the run is ERROR, not passed;
  - an unexpected error of a handler is ERROR, and the run is ERROR;
  - the run moves only along its states;
  - a step without a deadline runs to its end, bounded only by the scenario.
- Gates: `ruff format`, `ruff check`, `mypy` (strict, 51 source files), unit tests (204 pass), the licence check.

## Decisions

- D-017: the engine, the cursors, the deadlines, fail-fast, the verdicts and the run states.

## Points for the next tasks
