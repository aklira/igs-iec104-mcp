# B1 — Python project and tooling

## Prompt

Task B1 of `IMPLEMENTATION.md` §14, after the maintainer approved the proposed dependencies:
create the Python project, its tooling (ruff, mypy strict, pytest), the package skeleton of §12,
`AGENTS.md`, `DECISIONS.md`, `docs/ai-log/QUESTIONS.md`, and the CI running the Python part of the
gate. Pin the dependency versions of §11 in the lockfile.

## Summary

- `pyproject.toml` and `uv.lock` (committed). Runtime dependencies: `mcp`, `pydantic`, `httpx`,
  `docker`, `ruamel-yaml`, each with an upper major bound. Development dependencies: `ruff`, `mypy`,
  `pytest`, `pytest-asyncio`. The project is not packaged (`package = false`), see D-001.
- `.python-version` pins 3.12; `requires-python` is `>=3.12`.
- The package skeleton of §12 in `src/igs_iec104_mcp/`: `server`, `models`, `definitions`,
  `docker`, `runtime`, `scenarios`, `storage`, `reporting`. Each holds only its docstring; the
  tasks that fill them are named in the docstrings.
- `tests/unit`: 11 tests. The version matches `pyproject.toml`; each skeleton module imports; the
  safe YAML loader refuses a tag that builds a Python object (D-002).
- `scripts/check_licences.py`: a standard-library check of the installed licences against §2.
- `AGENTS.md`, `DECISIONS.md` (D-001 to D-003), `docs/ai-log/QUESTIONS.md` (Q-001).
- `.github/workflows/ci.yml`: the Python gate on Linux, with `uv sync --locked`.

Local results:

- `uv run ruff format --check`, `uv run ruff check`, `uv run mypy` and `uv run pytest tests/unit`
  pass.
- `scripts/check_licences.py` reports four distributions outside §2 (Q-001). It is not part of the
  CI gate until the policy is decided.

Not done in this task:

- CI has not run: it runs when the branch is pushed.
- `tests/integration` and `tests/e2e` are not created yet; they come with tasks D1 and M1.
- The Rust part of the gate comes with B2.
