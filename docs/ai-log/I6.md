# I6 — Client registration, Claude Code and Codex

## Prompt

Task I6 of `IMPLEMENTATION.md` §14 (Phase I, issue #1), a human gate. The maintainer validated the Q-004
recommendations on 2026-10-14 (D-061): user scope for Claude Code, global for Codex, no silent overwrite,
confirmation before a change, `--force` to replace a different entry, and `--yes` for a new entry only.
`scripts/install.sh --client claude|codex [--force] [--yes]` registers the server with the client's own CLI.

## Summary

- `src/igs_iec104_mcp/registration.py`: the desired registration (the venv's Python, `-m igs_iec104_mcp`, the project
  directory, the two images by identity, and the environment `PYTHONPATH` and `DOCKER_HOST`), the commands of each CLI,
  the reading of the existing entry, and the decision: nothing when it matches, a refusal when it differs without
  `--force`, and otherwise the exact commands, a confirmation, the change, and a check after it. It is run as
  `python -m igs_iec104_mcp.registration`.
- `scripts/install.sh`: `--client`, `--force`, and `--yes`; `generic` is refused with exit 2 (planned after v1). The
  engine's host is read from the preflight, so that the server uses the engine that was found. A dry run lists the
  registration as step 8 and runs nothing.
- Tests: `tests/unit/test_registration.py` (13: the commands, a fresh add, a repeat, a different entry refused and
  replaced, a declined confirmation, no terminal without `--yes`, a missing CLI, no environment value printed, and a
  failed add); `tests/integration/test_install.py` (9, with stub `claude` and `codex` CLIs that match the real ones).
- `DECISIONS.md`: D-061 (the decision). `docs/ai-log/QUESTIONS.md`: Q-004 closed. `IMPLEMENTATION.md`: I6 ticked.

## Found while testing

- With the real Codex CLI, `codex mcp get --json` prints a warning on stderr next to its JSON. The first version of the
  module read stdout and stderr together, and the JSON did not parse. The runner now keeps the two streams apart:
  stdout is data, stderr is a diagnostic.
- Claude's `mcp get` reports a broken entry with exit 0, and Claude refuses a duplicate name with exit 0 too. The module
  decides from the text and the entry, never from an exit code alone.
