# V4 — Release documentation and platform matrix (first part)

## Prompt

Task V4 of `IMPLEMENTATION.md` §14. The task depends on all the previous tasks, including three human gates (M4, X3, V3).
The user decided to start the documentation now (D-047). The platform matrix remains for later.

## Summary

- `README.md`: the overview, the list of the documents, and the status.
- `docs/setup.md`: prerequisites, building the runtime and the images (by identity), the project directory, the server
  options, the MCP client configuration, the Podman socket, the gates, and the integration tests.
- `docs/definitions.md`: the bench and scenario YAML, the points, the limits, the cleanup policy, TLS, the external
  targets, the actions, the schemas.
- `docs/docker.md`: the containers and their hardening, the networks, the control API through the relay, the published
  stations, the redundancy groups, the managed stops, the labels, and the recovery.
- `docs/tools.md`: the 19 tools with their arguments and results, the error codes, the run states, and the verdict
  outcomes.
- `docs/runs-and-artifacts.md`: the layout, the journal, the snapshots, the evidence, the reports, the retention, and
  the secrets.
- `docs/troubleshooting.md`: the symptoms that a user meets, their causes, and their fixes.
- `docs/platform-matrix.md`: the tested platforms and versions, the feature support, the limits of the upstream library
  at the pinned revision, the observed limitations, and what remains before a release.

No code changed. Dependencies: none.

## Verification

- Every fact was read from the code or the contracts: the options come from the help of the server and of the runtime;
  the error codes, the run states, the outcomes and the tool signatures come from the sources; the container hardening
  comes from the Docker adapter.
- The YAML snippets of the pages (the external target, the published station, a switchover scenario) are accepted by the
  server's validator.
- The internal links and anchors of the pages were checked: none is broken.
- The setup page's gate commands are those of the CI workflow (the Python gate, the Rust gate, the licence policy).
- The limits quoted from the upstream library come from its `docs/capabilities.md` at the pinned revision.
- The Python unit suite is unchanged by this part (no code change).

## Problems found

- The planner's refusal of an external connection says `external targets are not managed yet (task X1)`. X1 is done, so the
  message is out of date. The documentation states the current behaviour; the message belongs to the task that makes the
  connection.
- A first draft described two behaviours that the code does not have: a cleanup policy refused with an `unsupported`
  outcome (it is refused at run start with the error code `unsupported`), and `send_command` to a managed instance (it is
  unsupported). The pages were corrected against the code.
- The first draft of the troubleshooting page quoted a message that the server does not print. The entries now quote
  the messages of the code.
