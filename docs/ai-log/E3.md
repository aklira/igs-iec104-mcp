# E3 — Cancellation and cleanup

## Prompt

Task E3 of `IMPLEMENTATION.md` §14: cancellation of a run, and cleanup steps after success, failure, or
cancellation. Done when a cancelled run reports `cancelled`, runs its cleanup, and leaves no pending command.

## Summary

- `scenarios/engine.py`: `execute` takes a `cancel` event. A step in progress ends CANCELLED: its handler is
  cancelled and awaited (`_until_cancelled`), so its `finally` blocks run before the run ends. A cancel before a
  step stops the run before it. The cleanup steps (`_cleanup`) run after every outcome, outside fail-fast and the
  global deadline, each with a verdict `cleanup N: <action>`. A cleanup step without a timeout gets
  `CLEANUP_SECONDS`, so it is always bounded. `_status` gives ERROR, then CANCELLED, then FAILED, then PASSED.
- D-027 records the decisions, including what is not in E3 (`execution_seconds`) and the "no pending command" check.

Dependencies: none new.

## Verification

- `tests/unit/test_scenario_engine.py`: a cancelled step is stopped, its handler's `finally` ran (its request is
  closed) before the run ended, and the next step did not run; a cancel between steps stops before the next step;
  a run cancelled before it starts runs only its cleanup; cleanup runs after success, failure, and the global
  deadline; every cleanup step runs under fail-fast; a failed cleanup step fails a run that passed; an unsupported
  cleanup step is an error; a cleanup step is bounded by its deadline after the global one.
- Gates: `ruff format --check`, `ruff check`, `mypy` (strict), the unit suite (251 pass), and the engine tests five
  times with warnings as errors (20 pass each time).

## Decisions

- D-027: the cancel event; the handler is awaited after cancellation; cleanup is not cancelled and always has a
  deadline; a cancelled run stays CANCELLED even when a cleanup step failed (the failure is in the verdicts).

## Points for the next tasks

- `execution_seconds` is still not enforced; the run controller (M2 and D3) owns the bench's lifetime.
- The "no pending command" check becomes a real test when the command actions (send_command) get a handler.
- E2b (the runtime-backed source) and E4 (parallel branches) follow.
