# S5 — Runtime link flags

## Prompt

Task S5 of `IMPLEMENTATION.md` §14, added after D2 (D-020): the runtime takes the link parameters as flags
(`--t0` to `--t3`, `--k`, `--w`), checked with the upstream rules, with the defaults of §9.6 when they are absent.
The plan stops refusing link parameters. Done when unit tests cover each rule of the flags, and an integration
test shows that a short timeout changes the observed behaviour of a link.

## Summary

- `runtime/igs-iec104-runtime/src/config.rs`: the six flags; the upstream rule checked when the command line is
  read (`LinkConfig::new`); the parameters in the configuration; the configuration boxed in `Invocation::Run`;
  the usage text lists the flags.
- `src/client_role.rs`, `src/server_role.rs`, `src/runtime.rs`: the parameters go to the client
  (`with_parameters`, fallible) and to the station (`ServerConfig::parameters`); a rule refused at bind is a
  `BindError::Link` or a station error that names the parameter.
- `docker/plan.py`: all six flags are passed to every runtime; the refusal of link parameters is removed. Its
  unit test and the integration test that used it are replaced.
- D-025 records the decision.

Dependencies: none new. The upstream link crate is already a dependency of the runtime.

## Verification

- Rust, toolchain 1.99.0: `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test --locked --workspace`
  (118 tests). The new tests: the flag parsing and each rule in `config.rs` (7 tests), and the t1 behaviour test
  in `tests/client_role.rs`, which passes in 2 seconds with t1 of 2 seconds and fails after 10 seconds with the
  default t1 (checked by running it both ways).
- Python: `tests/unit` (218 pass), `mypy` strict, `ruff`.
- Integration: the contract and Milestone 1 tests with the local binary; and the Docker tests on the rebuilt image
  `igs-iec104-runtime:s5`, including the new bench with non-default parameters. 15 pass, no labelled resource left.

## Points for the next tasks

- The flags are part of the plan's runtime arguments, so a scenario that sets a parameter needs no change to the
  runtime. The timeouts (E5, the reconnection scenarios) can now be tested with short values.
- `execution_seconds` of the resource limits is still not enforced (E3).

About 200 lines changed across the runtime, the plan, and the tests. Within the roughly 400 lines of §2.
