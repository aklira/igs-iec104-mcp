# I3 — MCP handshake and bench validation in the doctor

## Prompt

Task I3 of `IMPLEMENTATION.md` §14 (Phase I, issue #1): the doctor starts the server with the stdio command a client
would use, performs the MCP handshake, lists the tools, and calls `bench_validate` on
`examples/benches/basic-pair.yaml`. Its JSON status gives the result of each check. Done when an integration test runs
the doctor on the built package and gets exit 0, and a wrong command path exits nonzero with a corrective step.

## Summary

- `src/igs_iec104_mcp/handshake.py`: the server's parameters (this interpreter, `-m igs_iec104_mcp --project DIR`, the
  source on `PYTHONPATH`), the exchange (handshake, tool list, `bench_validate`), the failure messages with the server's
  last stderr line, and a 60-second timeout. The project is temporary and removed.
- `src/igs_iec104_mcp/checks.py`: the `Status`, `Check`, and `Report` types, moved out of the doctor so that the doctor
  and the handshake do not import each other.
- `src/igs_iec104_mcp/doctor.py`: the handshake checks are appended to the host checks, and `--server-only` runs only
  them. `main` takes the server checks as a parameter, so its tests do not start a server.
- Tests: `tests/unit/test_handshake.py` (6), `tests/unit/test_doctor.py` (two new tests, and the two existing `main`
  tests now pass a no-op server), `tests/integration/test_doctor_handshake.py` (2, one of them through the entry point).
- `DECISIONS.md`: D-058. `IMPLEMENTATION.md`: I3 ticked in §16.
