# X1 — External target model and policy

## Prompt

Task X1 of `IMPLEMENTATION.md` §14: the external target model and policy. Depends on C4 and C2. Done when the control
plane refuses undeclared operations on a target, and a connectivity probe is explicit and opt-in.

## Summary

- `models/target.py`: `undeclared(target, required)` is the one rule that applies a target's allowed operations.
- `models/scenario.py`: the checker uses that rule for a command to an external target, so an undeclared operation is
  refused before any run starts.
- `definitions/targets.py`: the static report of a target, and the explicit TCP probe, with its timeout range.
- `server.py`: the `target_validate` tool (§9), with `probe` off by default.
- D-034 records the decisions and what is not in X1.

Dependencies: none new.

## Verification

- `tests/unit/test_external_targets.py` (8 tests) passes three times in a row with warnings as errors.
- The unit suite passes (330 tests), the stdio test lists fifteen tools, and the schema check matches the models.
- Gates: `ruff format --check`, `ruff check`, `mypy` (strict, 73 source files).
- Found while testing: a probe test that used a released port failed, because another test took the port in between.
  The test now binds a port and does not listen on it, so the port stays reserved and the connection is refused.

## Decisions

- D-034: the single policy rule; the static report and the explicit probe; what is not in X1.

## Points for the next tasks

- M3 adds the confirmation of state-changing operations on an external target, and the opt-in of the definition; the
  planner's refusal of external connections stays until X2 and M3 lift it together.
- X2 publishes the endpoints of the simulated servers that an external client reaches.
- The probe is TCP only; a later version may attempt the TLS handshake for a secured target, with its own opt-in.
