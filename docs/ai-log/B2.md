# B2 — Rust runtime skeleton and image

## Prompt

Task B2 of `IMPLEMENTATION.md` §14, after B1: create the `runtime/` workspace with `igs-iec104`
pinned by Git revision, the pinned toolchain, `deny.toml`, a binary that starts and exits, the
Dockerfile of §11, and CI building the image. Record the pinned revision in `DECISIONS.md`.

## Summary

- `runtime/`: a Cargo workspace (edition 2021, minimum Rust 1.85) with the crate
  `igs-iec104-runtime`. Its only dependency is `igs-iec104`, pinned by `rev` to
  `e91ecc824fcbc750262a5c8505c8812457d200c1` (D-004). `Cargo.lock` is committed.
- `runtime/rust-toolchain.toml` pins `1.99.0` (D-005).
- `runtime/deny.toml`: the licence list of §2, the one git source (the upstream repository), and
  the registry source.
- The binary prints one line, `igs-iec104-runtime <version> (IEC 60870-5-104 default port 2404)`,
  and exits with status 0. It forbids `unsafe` code. It has two unit tests.
- `docker/runtime.Dockerfile`: a build stage on `rust:1.99.0-trixie` with `libssl-dev`, and a
  runtime stage on `debian:trixie-slim` with `libssl3t64`, running as the non-root user `runtime`.
  The build context is `runtime/`, and `runtime/.dockerignore` excludes `target/`.
- CI (`.github/workflows/ci.yml`): a `rust-gate` job (format, clippy, tests, `cargo deny`), and an
  `image` job that builds the image, runs it and checks its banner, and uploads the image ID as the
  artifact `runtime-image-id`.
- `DECISIONS.md`: D-004 (upstream revision), D-005 (toolchain and base images), D-006 (OpenSSL
  backend, not `rustls`), D-007 (licences admitted for transitive dependencies, see B1).
- `tests/unit/test_runtime_pin.py`: checks that the pinned revision and the toolchain match the
  text of D-004 and D-005.
- `AGENTS.md`: the Rust gate commands.

Local results:

- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`,
  `cargo test --workspace --locked` (2 tests) and `cargo deny check` pass. `cargo deny` reports
  three licence allowances that no dependency uses (BSD-2-Clause, BSD-3-Clause, ISC), and one
  duplicate `syn` from two upstream dependencies. These are warnings; the list is kept as §2 gives
  it.
- The Python gate passes (28 unit tests, including the licence policy and the pins).

Verified with Podman (Docker is not installed here):

- `podman build --file docker/runtime.Dockerfile runtime` builds the image (about one minute).
- `podman run --rm <image>` prints the banner and exits with status 0.
- The process runs as `uid=999(runtime)`, not as root.
- `ldd` on the binary lists no OpenSSL library: the binary does not call OpenSSL yet, so the linker
  drops it (D-006). The image still installs `libssl3t64`, as §11 requires.

Not verified locally:

- The Docker build in CI, which runs after the branch is pushed. CI uses Docker, not Podman.
- The image ID is the local content ID. A registry digest is recorded when an image is published,
  which B2 does not do.

Open:
