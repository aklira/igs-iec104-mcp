# R1 — Run store

## Prompt

Task R1 of `IMPLEMENTATION.md` §14: the run store, with SQLite metadata, event journals, and an artifact index. Depends
on C5. The plan gives no done criterion of its own for R1; the general rule of the R tasks applies (its tests pass, and
its reports survive the cleanup of the test bench), and D-032 states it.

## Summary

- `storage/runs.py`: `RunStore`, with the run record in SQLite, the journal of events as JSON lines, and the artifacts as
  files indexed in SQLite.
- `models/run.py`: `TRANSITIONS` moves here from the engine, so the engine and the store use one table.
- D-032 records the layout, the bounds, and what is not in R1.

Dependencies: none new (`sqlite3` is in the standard library).

## Verification

- `tests/unit/test_run_store.py` (21 tests) pass with warnings as errors.
- The full unit suite passes (311), and the schema check matches the models.
- Gates: `ruff format --check`, `ruff check`, `mypy` (strict, 68 source files).

## Decisions

- D-032: the layout, the transitions in one table, the bounded journal with its dropped count, the write-once artifacts
  with their digest and size limit, and the cursors.

## Points for the next tasks

- D3 (reconciliation) reads these records after a restart and marks the runs that were running as interrupted.
- R2 (reports) reads the journal and the artifacts; R3 (retention) enforces the storage bounds across runs, and today
  only the per-run limits exist.
- M2 (run tools) uses this store for `run_get`, `run_events`, and the artifacts.
- The journal is read from its start for each page; an index is a later improvement if runs grow large.

## Size

About 410 lines of store and about 210 lines of tests, plus the move of the transition table. That is above the roughly
400 lines of §2 counting the tests: the store is one file with one job, and its layout is decided in a single record.
