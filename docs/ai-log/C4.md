# C4 — Definition models and YAML schemas

## Prompt

Task C4 of `IMPLEMENTATION.md` §14: typed models for the test bench, the instance, the external target,
the scenario, and the run; safe YAML loading; the validations of §5; and the JSON Schemas published from the
models. Done when the unit tests cover every rejection of §5 with an actionable message, and a check fails
when the published schemas differ from the models.

## Summary

- `models/common.py`: names, common addresses (1 to 65534), information object addresses (1 to 16777215),
  durations (`500ms`, `10s`, `5m`, `1h`), secret references (`secret:<name>`), the canonical hash, and the
  error type that carries each problem with its path.
- `models/points.py`: the ten monitoring kinds of the upstream `PointValue`, the form of each value, the
  kinds with a time-tagged form, the command policy, and the simulation (the rules the runtime applies).
- `models/instance.py`: the link parameters with the upstream rules, the resource limits, and an instance
  (a client serves no points; a point address is used once).
- `models/target.py`: an external target, its endpoint, its secrets (never key material), and its allowed
  operations (the state-changing ones are named).
- `models/bench.py`: the test bench as a whole: unique names, resolved references, the roles of the two ends
  of a connection, and the networks (an external target needs an external network).
- `models/scenario.py`: the scenario, its steps (a closed list of actions, with an error that names the list),
  and `check_scenario`, which resolves each step against its bench.
- `models/run.py`: a run, with a snapshot of its inputs whose hashes are checked, the status, the progress,
  the observations, the verdicts, and the artifacts.
- `models/loader.py`: the safe loader and the reading of each definition, with every problem and its path.
- `models/schemas.py`: the JSON Schemas of the three definitions, written to `contracts/definitions/`,
  with `--write` and `--check`.
- `examples/benches/basic-pair.yaml` and `examples/scenarios/interrogation-and-spontaneous-update.yaml`: the
  example of §8, with the point written as `kind`.

Dependencies: `pydantic` and `ruamel.yaml`, both approved at B1. No new dependency.

## Verification

- `tests/unit/test_models_common_and_points.py`: the addresses, the durations, each point kind's form, the
  time tags, the command policy, the simulation rules.
- `tests/unit/test_models_instance_and_bench.py`: the link parameters (each upstream rule), the limits, the
  client without points, the names, the networks, the connections, the external targets (secrets, ports,
  operations).
- `tests/unit/test_models_scenario_and_run.py`: the action list, the timeouts, the references, the commands
  against an external target's operations, the stop of a target, the snapshot hashes, the status and the
  progress.
- `tests/unit/test_models_loader.py`: a Python tag is refused, a key given twice is refused, every problem of
  a bench is reported with its path, and the examples load and cross-check.
- `tests/unit/test_models_schemas.py`: the committed schemas match the models; a changed schema, or a missing
  one, is reported; the check command fails on drift.
- Gates: format, lint, mypy in strict mode over the models and the tests, and the unit tests (136 pass).

## Decisions

- D-013: the models, the reading, the rules, and the published schemas.
- Q-002: the ten kinds of the definitions against the five the runtime serves.

## Points for the next tasks

- The plan's §8 syntax names the point's kind `type`. The definitions name it `kind`; C5 and the scenario
  engine (E1, E2) follow the definitions.
- The definitions are read from YAML and checked here, but not stored: the project directory, the path
  checks, the atomic writes, and the revision checks are C5.
- The timeouts are whole durations; the upstream recommendation of t3 at most 48 hours is not enforced
  (it is a recommendation, not an error, in the upstream library).
- The schemas are published from the models. A contract drift check against the runtime's API is C1's
  concern; the definitions are the controller's own contract.

## Size

About 3,800 lines in all: the models and their tests, and the generated schemas (about 1,200 lines of
JSON). It is far above the roughly 400 lines that §2 allows. The generated schemas are not written by hand,
and the models depend on each other, so the task is one change.
