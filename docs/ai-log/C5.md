# C5 — Definition storage

## Prompt

Task C5 of `IMPLEMENTATION.md` §14: the project directory, path traversal protection, atomic writes,
revision checks, and run snapshots. Done when the tests cover traversal attempts, concurrent updates with a
stale revision, and a snapshot unaffected by a later edit.

## Summary

- `definitions/store.py`: `ProjectStore` over one project directory (`benches/`, `scenarios/`, `runs/`).
  It reads a definition with its revision, writes it only at the revision it was read at (or as a new
  definition), lists the names, takes a run's snapshot, and reads it back with its hashes checked.
- Containment: names are checked before they become paths; paths are resolved, so a `..`, a name with a
  slash, or a symbolic link (to a file or a directory) that leads outside is refused. The lock file is not
  followed when it is a link.
- Atomic writes: a temporary file in the same directory, flushed, then replaced in one step; the temporary
  file is removed on failure. Writers hold an exclusive `flock` on `.lock`.
- Validation before writing: an invalid definition, or a file whose name differs from the definition's
  `name`, is not written.
- Snapshots: the bench and the scenario are checked against each other and frozen with their hashes, in
  `runs/<run-id>/snapshot.json`, written once.
- `DECISIONS.md` D-014 records the layout, the revisions, the locking, and the snapshots.

Dependencies: none added. The standard library (`fcntl`, `tempfile`, `os`, `hashlib`, `secrets`) and the
models of C4.

## Verification

- `tests/unit/test_definitions_store.py` (31 tests):
  - traversal: names with `..`, a slash, a leading slash, a dot, upper case, an empty name, and a 64-character
    name are refused for reads and writes;
  - symbolic links: a file link to the outside is neither read nor written; a directory link to the outside
    is refused; a lock file that is a link is not followed;
  - revisions: a stale update is refused with the message that tells to read again; a removed definition is
    reported; a new definition cannot replace an existing one;
  - concurrency: eight threads write at one revision, through a barrier; exactly one is written and seven are
    refused as stale;
  - atomicity: a failed replacement keeps the old text and leaves no temporary file;
  - validation: an invalid definition is not written; a file name that differs from the definition's name is
    refused;
  - snapshots: a snapshot is unaffected by a later edit of its scenario; a second snapshot of the same run is
    refused; a snapshot changed on disk is refused by its hashes; a snapshot needs its bench and scenario;
    a run identity that is not 32 hex digits is refused.
- Gates: `ruff format`, `ruff check`, `mypy` (strict, 40 source files), and the unit tests: 167 pass
  (136 before, 31 new).

## Decisions

- D-014: the layout, the revisions as SHA-256 of the bytes, the exclusive lock, and the write-once snapshots.
