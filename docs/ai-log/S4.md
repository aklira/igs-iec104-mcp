# S4 — Runtime point kinds (parts S4a to S4d)

## Prompt

Task S4 of `IMPLEMENTATION.md` §14, added after D2 (D-019): the runtime serves the five point kinds it does
not serve yet (counter, step, bitstring, packed, normalized-unqualified), on the station and in the client's
point image. This commit is the first part, S4a: `counter`. The rest is split (D-021).

## Summary

- `runtime/igs-iec104-runtime/src/points.rs`: the `counter` kind, with its form (a 32-bit integer), its JSON
  value, and the refusal of a ramp or a walk on a counter (those need a measured point).
- `src/image.rs`: the decoding of M_IT_NA_1 and M_IT_TB_1 into the point image, with the invalid flag as the
  quality.
- `src/lib.rs` and `contracts/`: the contract is 1.3.0, with `counter` in the point kinds of the API and the
  additive change recorded in both event schemas.
- `docker/plan.py`: `counter` is served, so a bench that uses it is accepted.
- D-021 records the decision and the split of S4.

Dependencies: none new.

  `cargo test --locked --workspace` (99 tests, including the new ones), and `cargo deny check`.

- The counter round trip is tested on the wire: a station serves a counter, an update is sent, and the upstream

  like the general interrogation: the activation confirmation, then the termination (cause 10). The readings
  (M_IT, cause 37) go to the image.
- The contract is 1.4.0 (a new route and a new request kind, both additive).
- Verification: `cargo fmt --check`, `cargo clippy -D warnings`, and `cargo test --locked --workspace` (101 tests,
  including the new correlator test and the three client role tests, one of them new). `cargo deny check` was
  not re-run for this part: no dependency changed.
- The Python method `ControlClient.counter_interrogation(group)` is one HTTP call; it is not covered by a Python
  integration test yet. The Rust test covers the same route over HTTP.
- The integration tests pass: the contract and Milestone 1 tests with the local binary, and the 12 Docker tests on
  the rebuilt image `igs-iec104-runtime:s4b`, with no labelled resource left behind (14 in all).

## Part S4c: step and bitstring

- `step` (M_ST_NA_1, M_ST_TB_1): the value is `{"value": -64..63, "transient": bool}`. `bitstring` (M_BO_NA_1,
  M_BO_TB_1): the value is an integer from 0 to 4294967295, with bit n (1 to 32) the bit of 2^(n - 1) (D-023).
- The contract is 1.5.0 (two additive point kinds).
- Verification: `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test --locked --workspace` (106 tests),
  including the forms, the refusals, the image decoding, and the station round trip of both kinds. The Python
  plan serves the two kinds; its refusal test now names `normalized_unqualified` and `packed`, the kinds not
  served yet. The contract and Milestone 1 tests pass with the local binary.
- The integration tests pass on the rebuilt image `igs-iec104-runtime:s4c`: 14 in all (the contract and
  Milestone 1 tests with the local binary, and the 12 Docker tests), with no labelled resource left behind.
- The remaining kinds are `packed` and `normalized_unqualified` (S4d).

## Part S4d: packed and normalized-unqualified (all ten kinds)

- `packed` (M_PS_NA_1): `{"status": 0..65535, "change": 0..65535}`, bit n (1 to 16) is point n (D-024). Its value
  is decoded with its quality. `normalized_unqualified` (M_ME_ND_1): a normalized number, with no quality flag set.
- The contract is 1.6.0 (two additive point kinds, so all ten monitoring kinds are in the contract).
- The plan serves all ten kinds: the refusal by name is kept for a future kind, and tested by lowering the served
  set. A test checks that the served set equals the model's kinds.
- Verification: `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test --locked --workspace` (110 tests),
  the contract and Milestone 1 tests with the local binary (2 pass), and `tests/unit` (217 pass).
- One station test failed once in the first full run of the station binary (the event-loss test, which waits up
  to 10 seconds for dropped events under load). It passed in the next five full runs and in fifteen isolated
  runs; it is recorded here and not attributed to S4d.
- The integration tests pass on the rebuilt image `igs-iec104-runtime:s4d`: 14 in all, with no labelled resource
  left behind.
