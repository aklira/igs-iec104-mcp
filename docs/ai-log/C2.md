# C2 — Client role: correlation, generations, point image

## Prompt

Task C2 of `IMPLEMENTATION.md` §14: the owner task with `OfflineRequests::Discard`, the connection
generations from the `Connected` events, the binding of requests to generations by
`Delivery::Transmitted`, correlation with `answer::judge` within the generation, the verdicts of §7,
and the client-side point image. Done when the tests cover confirmed, refused (negative and causes 44
to 47), timed out, cancelled, indeterminate (generation ended), and not sent (discarded), and a command
is refused while the transfer is not started.

## Summary

- `correlation.rs`: a pure state machine (no I/O, an injected clock) for the requests. It holds the
  connection generation, the open and recent requests, and the verdicts. The rules are in its module
  documentation. Open requests are bounded (`MAX_IN_FLIGHT = 8`), and two open requests cannot share a
  type and an address.
- `image.rs`: the client's point image, decoded from the ASDUs of the single, double, and measured types
  (plain and time-tagged, individual and sequence forms).
- `client_role.rs`: the owner records every event with its generation, and applies the correlator and
  the image to each one. The verdicts are recorded as `verdict` events. The owner computes the deadlines
  with tokio's clock. The client's channels have a capacity of 32, which is above the bound on open
  requests: the owner never waits for room in the command channel while the events it would read are
  waiting (the risk noted in S1).
- `api.rs`: the commands, the request records, the cancellation, and the image.
- Contract 1.1.0 (`contracts/`): the generation on every event, the `verdict` kind, the new routes and
  their schemas. Both files and the readiness answer name the version (D-011).

Dependencies: none added.

## Verification

- Rust, unit: 16 tests of the correlator (the confirmation and termination of each kind, the negative
  and 44–47 refusals, the deadline, cancellation with and without a write, the discard, the indeterminate
  end, the generation rule, the busy address, the open bound, and the retention), 8 tests of the image.
- Rust, integration (`tests/client_correlation.rs`, 8 tests): against the upstream station, a selection,
  an execution, and an interrogation are confirmed, and the image holds the station's value with its
  cause and generation; a selection of an unknown address is refused with cause 47 as a negative
  confirmation; an execution without its selection is refused with cause 7 as a negative confirmation,
  as the station requires; a command before the transfer starts is refused with `409`. Against a silent
  peer that answers the start of the transfer and nothing else: a command times out after it was written;
  a command cut off by the connection is `indeterminate`, with its generation; a cancelled command says
  it was written, and a second cancellation is refused.
- Python: the contract test now also covers the command, the request record, the cancellation, the
  image, and the refusal codes, against a real station and client (40 Python tests pass).
- Gates: clippy with warnings as errors, `cargo test`, `cargo deny`, the Python checks, and the image
  build with Podman (its banner prints).

## Points for the next tasks

- `not_sent` is reached end to end only through a race. The correlator rule is tested, and the discard
  event is tested in S1; a forced end-to-end case would need a control of the write that the library does
  not offer.
- The verdicts of the interrogation and of an execution are only final at the termination. A station
  that confirms but never terminates is `timed_out`, after its deadline (30 seconds for an interrogation,
  by default 10 seconds for a command, and at most 60 seconds).
- The image keeps the last value of each point across connections. Each value records the generation it
  arrived in, so a reader can tell a value of an earlier connection; the image does not clear on a
  reconnection.
- The start of the transfer is not a tracked request (its verdict is the `transfer` event). The stop of
  the transfer is not exposed yet.
- Command types other than the single command (double, regulating step, set points, clock, test) are not
  in the API yet; the rules of the correlator apply to them unchanged.
