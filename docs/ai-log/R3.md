# R3 — Limits and retention

## Prompt

Task R3 of `IMPLEMENTATION.md` §14: limits and retention: event buffers, storage bounds, and a retention policy.
Depends on R1 and D2. Done when its tests pass and its reports survive the removal of the test bench.

## Summary

- `runtime/source.py`: `events_after` reads the oldest sequence number the log kept; events dropped after the step's
  cursor raise `EventGap`, which makes the step an error, not a failure and not a pass by absence.
- `runtime/api.py`: `station_events`, the station's event route, with its drop count.
- `scenarios/runner.py`: at the end of a scenario, each runtime's drop count is read; a drop, or a count that cannot be
  read, is a `gap` event in the journal. `Runner.prune` removes the ended runs the policy selects, with a dry run by
  default, and keeps a run whose bench is still on the engine.
- `storage/retention.py`: `RetentionPolicy` (by count and by age), a pure selection.
- `storage/runs.py`: `RunStore.delete` removes an ended run with its index, journal, artifacts, and evidence.
- `reporting/reports.py`: a `gap` is a note of the report.
- `server.py`: `--keep-runs`, `--keep-days`, `--max-events`; the tool `run_prune(dry_run)`.
- D-040 records the decisions, and what is not in R3.

Dependencies: none new.

## Verification

- `tests/unit/test_retention.py` (11 tests) and the two new source tests pass. The unit suite and the MCP stdio test
  pass (393 tests), with the tool list naming `run_prune`.
- `tests/integration/test_mcp_run.py` and `tests/integration/test_mcp_report.py` pass on Podman. The report of a healthy
  run has no gap, so the drop reads on the real runtimes come back clean.
- Gates: `ruff format --check`, `ruff check`, `mypy` (strict, 85 source files), and the schema check.

## Decisions

- D-040: the event buffer rule, the drop counts at the end of a run, the storage bounds, the retention, and what is not
  in R3.

## Open

- A total size quota for the store is not in R3. The journal and artifact bounds limit each run only.
- Pruning is explicit. A scheduled prune is a later decision, since it removes evidence.

## Points for the next tasks

- V1 (TLS) and V2 (redundancy) will produce events the assertions read; the step-level gap check applies to them as it
  does now.
- A run that ends with an `EventGap` error keeps its evidence, and its report names the step.
