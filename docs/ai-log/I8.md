## Review

The review followed the guide's steps in a copy of the working tree, not in a clean clone. The changes are not committed,
so a clone cannot contain them. The copy excluded `.venv` and `runtime/target`. It used a temporary `HOME` for the client
configuration and the state, and the real `uv` and `rustup` caches. The Podman service was started as step 2 says.

- Step 1 (dry run): as written, with eight steps.
- Step 3 (install): stopped at the registration with `not a terminal: run again with --yes`, as the guide says. The
  approved run registered the server, and a second run printed `state unchanged` and `nothing changes`.
- Step 5 (level 1): `All required checks passed.`, exit 0. `claude mcp get igs-iec104` reported `Connected`.
- Step 6 (level 2): `bench-run ok ... 6 of 6 verdicts` and `bench-cleanup ok`, with no container, network, or temporary
  project left.

## Found while reviewing

- A first run failed at the Rust check: with a changed `HOME`, rustup could not find its toolchain. This is the review's
  isolation, and the guide's steps do not change `HOME`. The fix was to point `RUSTUP_HOME` and `CARGO_HOME` at the real
  directories. The rustc message was improved, as above.
- A level 2 run found no image on the engine. The images were in the storage of the changed `HOME`, and Podman keeps
  each user's images in that user's storage. The engine service and the doctor must run as the same user with the same
  `HOME`. The guide now has a row for this message.
- `--project-dir ~/igs-project` in the guide expands `~` before the shell runs the command, so it names the real home
  directory. The review's project was removed afterwards, since it had not existed before the review.
