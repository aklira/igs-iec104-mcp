# D3 — Reconciliation

## Prompt

Task D3 of `IMPLEMENTATION.md` §14: reconciliation. Depends on D2 and R1. Produce: startup reconciliation of stored state
with labelled resources; inspection and explicit cleanup of recovered test benches. Done when a controller killed during
a run restarts, marks the run interrupted, keeps its evidence, and does not resume commands.

## Summary

- `storage/runs.py`: `RunStore.unended()` lists the pending and running runs.
- `docker/adapter.py`: `DockerAdapter.owners(project)` lists the owners of the labelled resources of a project, one per
  run and bench, from their labels.
- `docker/bench.py`: `recover(adapter, owner, evidence)` keeps the logs and records of the containers of a bench in the
  run's evidence, then removes the owner's resources.
- `scenarios/runner.py`: `Runner.reconcile()` marks the unended runs that this server does not run as interrupted;
  `Runner.recovered()` lists the benches the engine holds for runs this server does not run; `Runner.remove_recovered()`
  removes one. The engines gain `owners` and `recover`.
- `server.py`: `create_server` reconciles at start and logs the runs it marks. Two tools: `bench_recovered` and
  `bench_recovered_remove`.
- D-037 records the decisions, and D-036 closes X2 on the Linux result.

Dependencies: none new.

## Verification

- `tests/unit/test_run_reconcile.py` (9 tests): a running run and a pending run are marked interrupted, with their journal
  kept and no bench started; a run this server runs is not reconciled; an ended run is left alone; the recovered list
  excludes the running runs; a removal names its evidence; a bench of a running run is refused; an unknown run is not
  found; without an engine, listing and removal are refused with `engine_unavailable`.
- `tests/integration/test_docker_reconcile.py` passes on Podman: a controller process is killed with SIGKILL after its
  first step; a new controller marks the run interrupted, lists its bench, removes it with the container logs kept in the
  evidence, and finds no owned resource left.
- The Docker integration tests (adapter, bench, publish, runs) pass on Podman with the runtime and relay images of this
  repository, and the publish test with the runtime binary (`IGS_RUNTIME_BINARY`), which an earlier run had skipped.
- The unit suite and the MCP stdio test pass (353 tests); the tool list names the two new tools.
- Gates: `ruff format`, `ruff check`, `mypy` (strict).

## Decisions

## Points for the next tasks

- A command that was in flight when the controller stopped has an unknown outcome. The run records `interrupted` and no
  verdict for it. A step that reports its own indeterminate outcome (M3 and the confirmation policy) is the place to
  record that, if it is needed.
- The listing shows every bench of the project that no task of this server runs, including a run that ended with a bench
  it could not remove (status `error`). That is deliberate: it is what an operator needs to inspect.
- A restart of a managed bench still needs a fixed station port (D2).
