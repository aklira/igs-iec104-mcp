# M4 — Streamable HTTP transport

## Prompt

Task M4 of `IMPLEMENTATION.md` §14, a human gate: "a maintainer has reviewed the authentication design and the exposure".
The maintainer chose the scope the recommendation proposed: the loopback only, one bearer token, no OAuth in this task.

## Summary

- `src/igs_iec104_mcp/transport.py`: the token file rules, the token verifier (constant-time comparison), the HTTP
  settings (loopback only, a port, the token), the server options, and the SDK's Host and Origin checks.
- `src/igs_iec104_mcp/server.py`: `create_server` takes the HTTP settings; `main` takes `--transport {stdio,http}`,
  `--http-host`, `--http-port`, and `--http-token-file`; stdio stays the default.
- D-048 records the decisions.

Dependencies: none new. The SDK's own run path serves the HTTP application, so `uvicorn` is not imported here.

## Verification

- `tests/unit/test_transport.py` (18 tests) passes. The unit suite passes (454 tests) with ruff, ruff format and mypy strict.
- The HTTP application was driven in process: no token gets `401`, a foreign `Host` gets `421`, a foreign `Origin` gets
  `403`, the right token gets the initialize result, and `tools/list` gets the 19 tools.
- On a real port (`127.0.0.1:8765`), checked with `curl`: `401` without the token, `200` with it, `421` for a foreign
  `Host`. The token does not appear in the server's log.
- The full integration suite passes after the change: 35 tests, none skipped, with the release binary and both images (Podman).

## Problems found

- The SDK warns when `validate_token_resource` is not set. It is set to false, because the token is the server's own and
  carries no resource indicator; the reasoning is in D-048.
- The SDK's authorization settings require an issuer URL. The server runs no authorization server, so the issuer is the
  server itself; a client is given the token out of band. This is documented in `docs/setup.md`.

## Decisions

- D-048: loopback only, one token, the SDK's checks, no remote listener and no TLS, no OAuth.

## Open

- A remote listener needs TLS and an authorization server: a separate decision.
- The Docker Desktop and WSL check of V4 does not depend on this task.

## Points for the next tasks

- If a remote listener is wanted, it starts with TLS for the HTTP listener and an authorization server, and a new decision.

## Size

About 200 lines of transport and command-line changes, and about 230 lines of tests and documentation.
