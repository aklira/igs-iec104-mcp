# R2 — Reports

## Prompt

Task R2 of `IMPLEMENTATION.md` §14: reports in JSON and JUnit XML, and a readable summary with the manifest of §10.
Depends on R1 and E2. Done when its tests pass and its reports survive the removal of the test bench.

## Summary

- `reporting/reports.py`: one document built from a run's record, journal, snapshot, evidence, and artifacts. The JUnit
  XML and the summary are rendered from it. Each step's outcome is sorted into a category (assertion failure,
  infrastructure error, timeout, unsupported, cancelled, indeterminate, passed). `report_of` makes a report once, after
  the run has ended, stores it as an artifact, and reads it back afterwards.
- `scenarios/engine.py`, `models/run.py`: each verdict carries the step's duration (`seconds`), timed-out steps included.
- `scenarios/runner.py`: a run records an `engine` event with the image identities and the upstream revision before its
  bench starts; `Runner.report` delegates to `report_of`.
- `runtime/pin.py`: the upstream revision, checked against the runtime's manifest by a unit test.
- `server.py`: the tool `run_report(run_id, format)` with `json`, `junit`, or `summary`.
- D-039 records the decisions, and what is not in R2.

Dependencies: none new (`xml.etree` is in the standard library).
